# ROLLER22G Roller Blind (Bluetooth)

블루투스 스캔에서 `ROLLER22G`라는 이름으로 나타나는 전동 롤스크린 모터를 Home Assistant에 연동하기 위한 커스텀 통합입니다.

A Home Assistant custom integration for roller blind motors that advertise over Bluetooth LE as `ROLLER22G`. The documentation is written in Korean.

> [!IMPORTANT]
> 실험적인 통합입니다. 모터 1대를 측정한 결과를 바탕으로 만들었으며, 다른 개체에서도 동일하게 동작하는지는 확인되지 않았습니다. 확인된 범위는 [검증 상태](#검증-상태)를 참고해 주십시오.

## 배경

이 모터는 제조사 앱과 리모컨으로 제어하며, Home Assistant용 공식 통합은 없습니다. 모터가 제공하는 GATT 구성은 다음과 같습니다.

| 역할 | UUID | 속성 |
| --- | --- | --- |
| 제어 서비스 | `00010203-0405-0607-0809-0a0b0c0d1910` | |
| 명령 | `00010405-0405-0607-0809-0a0b0c0d1910` | write |
| 응답 | `00010304-0405-0607-0809-0a0b0c0d1910` | notify |

이 구성은 다른 이름으로 판매되는 모터의 공개된 프로토콜 분석([프로토콜](#프로토콜) 참고)과 일치합니다. 다만 UUID가 같다는 사실만으로 명령 헤더와 로그인 방식까지 같다고 볼 수는 없으므로, 이 버전은 그 부분을 먼저 확인합니다.

## 요구 사항

| 항목 | 조건 |
| --- | --- |
| Home Assistant | 2026.2 이상 |
| 블루투스 | Home Assistant의 블루투스 통합이 동작하고, 모터에 연결할 수 있는 어댑터 또는 프록시가 있어야 합니다. |

## 설치

1. Home Assistant의 Marketplace(구 HACS)에서 이 저장소를 커스텀 저장소(Integration)로 추가합니다.
2. `ROLLER22G Roller Blind (Bluetooth)`를 설치한 뒤 Home Assistant를 다시 시작합니다.

## 설정

**설정 > 기기 및 서비스 > 통합 추가**에서 `ROLLER22G`를 선택하고 모터의 블루투스 주소를 입력합니다. 블루투스 통합이 모터를 발견한 경우에는 발견된 기기 목록에서 추가할 수도 있습니다. 추가하면 현재 위치를 한 번 읽습니다. 모터를 움직이지 않습니다.

## 제공 기능

모터마다 기기 하나와 다음 엔티티가 만들어집니다.

| 엔티티 | 설명 |
| --- | --- |
| 커버 | 열기, 닫기, 정지, 위치 지정을 지원합니다. 위치 100이 완전히 올린 상태입니다. |
| 배터리 (센서, 진단) | 모터가 상태 프레임으로 보고하는 배터리 상태입니다. 정상, 부족, 배터리 없음의 세 단계이며 잔량(%)은 아닙니다. 통신이 있을 때만 갱신됩니다. |
| 위치 읽기 (버튼, 진단) | 모터에 연결해 현재 위치를 읽습니다. 리모컨이나 제조사 앱으로 움직인 뒤 값을 맞출 때 사용합니다. |
| 마지막 통신 결과 (센서, 진단) | 마지막 통신의 결과를 상태로, 주고받은 프레임과 각 프레임의 송신 시각을 속성으로 제공합니다. |
| 읽기 전용 검증 실행 (버튼, 진단) | 프로토콜 확인용입니다. 기본적으로 비활성화되어 있습니다. |
| 검증 결과 (센서, 진단) | 읽기 전용 검증의 결과입니다. 기본적으로 비활성화되어 있습니다. |

커버의 속성 `reported_position`은 모터가 마지막으로 보고한 위치이고, `position_is_estimate`는 현재 표시 중인 위치가 추정값인지를 나타냅니다.

## 동작 방식

모터는 위치 명령을 받으면 그 위치까지 이동한 뒤 스스로 멈춥니다. 이 통합은 이동을 지켜보지 않으며, 통신할 때만 연결하고 곧바로 끊습니다.

| 동작 | 통신 |
| --- | --- |
| 열기, 닫기, 위치 지정 | 연결, 현재 위치 조회 1회, 위치 명령 1회, 연결 해제 |
| 이동 중 | 통신하지 않습니다. 표시되는 위치는 이동 속도로 계산한 추정값입니다. |
| 예상 도착 시각 + 3초 | 연결, 위치 조회 1회, 연결 해제. 아직 이동 중이면 남은 거리에 맞춰 다시 조회합니다(최대 6회). 목표에 이르지 못한 채 멈춰 있으면 그 위치를 표시합니다. |
| 정지 | 연결, 정지 명령 1회, 위치 조회 1회, 연결 해제 |
| Home Assistant 시작 | 위치 조회 1회. 모터를 움직이지 않습니다. |

보내는 프레임은 상태 조회, 정지, 위치 지정 세 종류입니다(읽기 전용 검증은 여기에 로그인이 더해집니다). 한계 설정, 타이머, 시계, 비밀번호 변경 프레임은 보내지 않습니다.

## 제한 사항

- 명령을 보낼 때마다 연결을 새로 맺으므로, 지시한 뒤 모터가 반응하기까지 수 초가 걸립니다. 정지도 마찬가지입니다.
- 이동 중에 표시되는 위치는 추정값입니다. 추정에 쓰는 속도(내릴 때 초당 약 1.19%, 올릴 때 약 0.94%)는 모터 1대에서 측정한 값이며, 블라인드의 길이와 무게에 따라 달라질 수 있습니다. 속도가 맞지 않아도 동작에는 영향이 없고, 도착 확인이 한두 번 더 이루어질 뿐입니다.
- 리모컨이나 제조사 앱으로 움직인 결과는 다음 통신 전까지 반영되지 않습니다.
- 모터는 블루투스 연결을 동시에 하나만 받는 것으로 알려져 있어, 제조사 앱이 연결되어 있는 동안에는 명령이 실패할 수 있습니다.
- 통신은 암호화되지 않으며, 이 통합이 쓰는 명령에는 로그인이 필요하지 않았습니다. 블루투스 도달 범위 안에서는 누구나 같은 명령을 보낼 수 있다는 뜻입니다.

## 검증 상태

모터 1대(2026-11-25)에서 확인한 내용입니다.

| 항목 | 상태 |
| --- | --- |
| 상태 조회 | 확인했습니다. 로그인 없이, 헤더 58과 78 모두에 상태 프레임이 돌아왔습니다. |
| 위치 값의 방향 | 확인했습니다. 완전히 올린 상태에서 위치 100%, 원값 1000이 보고되었습니다. |
| 위치 지정 | 확인했습니다. 로그인 없이 헤더 58로 전 구간(0~100%)을 이동시켰고, 모터가 목표 위치(원값 오차 1 이내)에서 스스로 멈췄습니다. 완전히 내린 상태에서는 위치 0%, 원값 0이 보고되었습니다. |
| 이동 중 정지 | 확인했습니다. 정지 프레임 송신 후 약 0.4~0.5초 뒤 모터가 정지를 보고했습니다. 새로 연결해 정지시키는 경우 지시부터 정지 프레임 송신까지 약 1초가 걸렸습니다. |
| 이동 속도 | 정지 상태에서 출발해 내릴 때 41%를 34.5초, 올릴 때 33%를 35.4초에 이동했습니다. |
| 도착 보고 | 연결이 유지된 경우 모터가 도착 시 상태 프레임(`D2`)을 보냈습니다. 이 통합은 이 보고에 의존하지 않습니다. |
| 로그인 | 다른 모터에 알려진 기본 비밀번호(`xxxxxx`)는 거부되었습니다(`D4 00 00`). |
| 연결 유지 시간 | 연결을 9초 넘게 유지한 5회 가운데 3회가 첫 프레임 송신 후 9~11초에 끊겼습니다. 원인은 확인되지 않았습니다. 연결이 끊겨도 모터는 받은 명령을 끝까지 수행했습니다. |
| 헤더 78의 이동 명령 | 확인되지 않았습니다. |
| 이동 중에 새 위치 명령을 보낸 경우 | 확인되지 않았습니다. |

확인된 상태 프레임은 `FF 01 02 03 D1 02 64 E8 03 9E 4E`입니다. 끝의 2바이트는 참고한 분석에 없는 값이며 의미를 확인하지 못했습니다. 프레임 생성과 응답 해석, 통합의 동작은 모의 모터를 대상으로 한 테스트로도 확인합니다.

## 프로토콜

프레임 구조는 아래 두 프로젝트가 공개한 분석을 따릅니다. 두 프로젝트는 같은 GATT 구성을 쓰는 다른 이름의 모터를 다루며, 명령 헤더(58, 78)와 로그인 필요 여부가 서로 다릅니다.

- [viggfred/blissble](https://github.com/viggfred/blissble) (MIT)
- [mistermej/Bliss-Smartblinds](https://github.com/mistermej/Bliss-Smartblinds) (MIT)

| 구분 | 형식 |
| --- | --- |
| 명령 | 헤더 4바이트 + 명령 코드 + 하위 코드 + 데이터 |
| 로그인 | `FF 03 03 03 03` + 비밀번호(6바이트 이상, 부족하면 0으로 채움) |
| 응답 | `FF 01 02 03` + 응답 코드 + 데이터 |
| 정지 | 헤더 + `5F 03 01` |
| 위치 지정 | 헤더 + `BF 03` + 위치 원값 2바이트(리틀 엔디언, 0~1000) |
| 상태 응답 (`D1`, `D2`) | 플래그 1바이트, 위치(%) 1바이트, 위치 원값 2바이트(리틀 엔디언) |
| 로그인 응답 (`D4`) | 데이터의 두 번째 바이트가 0보다 크면 성공 |
