# ROLLER22G Roller Blind (Bluetooth)

블루투스 스캔에서 `ROLLER22G`라는 이름으로 나타나는 전동 롤스크린 모터를 Home Assistant에 연동하기 위한 커스텀 통합입니다.

A Home Assistant custom integration for roller blind motors that advertise over Bluetooth LE as `ROLLER22G`. The documentation is written in Korean.

> [!IMPORTANT]
> 현재 버전(0.0.1)은 프로토콜을 확인하는 단계입니다. 모터에 로그인과 상태 조회만 보내며, 블라인드를 움직이는 기능은 없습니다. 확인된 범위는 [검증 상태](#검증-상태)를 참고해 주십시오.

## 배경

이 모터는 제조사 앱과 리모컨으로 제어하며, Home Assistant용 공식 통합은 없습니다. 모터가 제공하는 GATT 구성은 다음과 같습니다.

| 역할 | UUID | 속성 |
| --- | --- | --- |
| 제어 서비스 | `00010203-0405-0607-0809-0a0b0c0d1910` | |
| 명령 | `00010405-0405-0607-0809-0a0b0c0d1910` | write |
| 응답 | `00010304-0405-0607-0809-0a0b0c0d1910` | notify |

이 구성은 다른 이름으로 판매되는 모터의 공개된 프로토콜 분석([프로토콜](#프로토콜) 참고)과 일치합니다. 다만 UUID가 같다는 사실만으로 명령 헤더와 로그인 방식까지 같다고 볼 수는 없으므로, 이 버전은 그 부분을 먼저 확인합니다.

## 요구 사항

| 항목 | 조건 |
| --- | --- |
| Home Assistant | 2026.2 이상 |
| 블루투스 | Home Assistant의 블루투스 통합이 동작하고, 모터에 연결할 수 있는 어댑터 또는 프록시가 있어야 합니다. |
| 제조사 앱 | 검증을 실행하는 동안에는 종료해 두어야 합니다. 모터는 블루투스 연결을 동시에 하나만 받습니다. |

## 설치

1. Home Assistant의 Marketplace(구 HACS)에서 이 저장소를 커스텀 저장소(Integration)로 추가합니다.
2. `ROLLER22G Roller Blind (Bluetooth)`를 설치한 뒤 Home Assistant를 다시 시작합니다.

## 설정

**설정 > 기기 및 서비스 > 통합 추가**에서 `ROLLER22G`를 선택하고 모터의 블루투스 주소를 입력합니다. 블루투스 통합이 모터를 발견한 경우에는 발견된 기기 목록에서 추가할 수도 있습니다. 추가하는 과정에서는 모터로 아무것도 보내지 않습니다.

## 제공 기능

모터마다 다음 두 엔티티가 만들어집니다.

| 엔티티 | 설명 |
| --- | --- |
| 읽기 전용 검증 실행 (버튼) | 모터에 연결해 아래 순서의 프레임을 보내고 응답을 기록한 뒤 연결을 끊습니다. |
| 검증 결과 (센서) | 판정 결과를 상태로, 주고받은 모든 프레임을 속성으로 제공합니다. |

검증이 보내는 프레임은 상태 조회와 로그인 두 종류뿐입니다. 이동, 한계 설정, 타이머, 시계, 비밀번호 변경 프레임은 보내지 않습니다.

| 순서 | 프레임 | 목적 |
| --- | --- | --- |
| 1 | `FF 58 EA 41 D1 03 01` | 로그인 없이 상태 조회에 응답하는지 확인 (헤더 58) |
| 2 | `FF 78 EA 41 D1 03 01` | 로그인 없이 상태 조회에 응답하는지 확인 (헤더 78) |
| 3 | `FF 03 03 03 03 78 78 78 78 78 78` | 로그인 |
| 4 | `FF 58 EA 41 D1 03 01` | 로그인 후 상태 조회 (헤더 58) |
| 5 | `FF 78 EA 41 D1 03 01` | 로그인 후 상태 조회 (헤더 78) |

판정 결과는 다음과 같습니다.

| 상태 | 의미 |
| --- | --- |
| `match_header_58` | 헤더 58 상태 조회에 상태 프레임이 돌아왔습니다. |
| `match_header_78` | 헤더 78 상태 조회에 상태 프레임이 돌아왔습니다. |
| `login_only` | 로그인은 받아들여졌으나 상태 프레임은 오지 않았습니다. |
| `no_response` | 해석 가능한 응답이 없었습니다. |
| `device_not_found` | 연결 가능한 광고가 수신되지 않았습니다. |
| `connect_failed` | 연결에 실패했습니다. |

## 검증 상태

| 항목 | 상태 |
| --- | --- |
| 프레임 생성과 응답 해석 | 단위 테스트로 확인했습니다. |
| 검증 절차의 동작 | 모의 모터를 대상으로 한 테스트로 확인했습니다. |
| 실제 ROLLER22G 모터의 응답 | 아직 확인되지 않았습니다. |

## 프로토콜

프레임 구조는 아래 두 프로젝트가 공개한 분석을 따릅니다. 두 프로젝트는 같은 GATT 구성을 쓰는 다른 이름의 모터를 다루며, 명령 헤더(58, 78)와 로그인 필요 여부가 서로 다릅니다.

- [viggfred/blissble](https://github.com/viggfred/blissble) (MIT)
- [mistermej/Bliss-Smartblinds](https://github.com/mistermej/Bliss-Smartblinds) (MIT)

| 구분 | 형식 |
| --- | --- |
| 명령 | 헤더 4바이트 + 명령 코드 + 하위 코드 + 데이터 |
| 로그인 | `FF 03 03 03 03` + 비밀번호(6바이트 이상, 부족하면 0으로 채움) |
| 응답 | `FF 01 02 03` + 응답 코드 + 데이터 |
| 상태 응답 (`D1`, `D2`) | 플래그 1바이트, 위치(%) 1바이트, 위치 원값 2바이트(리틀 엔디언) |
| 로그인 응답 (`D4`) | 데이터의 두 번째 바이트가 0보다 크면 성공 |
